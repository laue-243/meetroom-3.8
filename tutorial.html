MeetRoom

Video calls, chat, file sharing and a shared code editor in one web page. Up to 10 people per room, no accounts and no installs.

What it is

MeetRoom is a single web page. One person creates a room and gets a 6-character code. Anyone with that code (or the invite link) can join. Everyone then connects directly to each other from their browsers, so there is no meeting server in the middle carrying your video.

In a room you can
  • See and hear everyone
  • Mute yourself and turn your camera on and off
  • Share your screen
  • Chat and send files
  • Edit code together in a VS Code style editor
The room creator (host) can
  • Mute people or stop their video
  • Stop guests from turning mic or video back on
  • Remove people from the room
  • Ban people so they cannot rejoin

Quick start

  1. Open MeetRoom in Chrome, Edge, Firefox or Safari. You land on the home page, which has Home, Features, Tutorial and Feedback tabs.
  2. Type your name and click Start meeting. Allow the camera and microphone when your browser asks.
  3. Click "Copy invite link" at the top and send it to the people you want. They open the link, type a name and click Join.
  4. Talk. Their video appears as tiles as they arrive.

The home page

The home page is where everything starts. It has a tab bar across the top:

The ⚙ Settings button at the right of the tab bar opens your settings. Inside a meeting, the ? button in the top bar opens this tutorial.

Starting and joining a meeting

Start

Click Start meeting on the home page. You become the host and get a random 6-character code shown at the top of the room with a Host badge.

Join

Type the code into the code box and click Join, or just open the invite link, which fills the code in for you. Codes are not case sensitive.

Room full

A room holds 10 people: the host plus 9 guests. An 11th person sees "This room is full".

No camera or microphone?

You can still join. MeetRoom lets you in without them, and you can chat, share your screen, send files and edit code. If you deny permission by mistake, click the lock icon in your browser's address bar, allow camera and microphone, and reload.

Anyone with the code can join, so share it only with people you trust. The host can remove or ban people who should not be there.

Video, microphone and screen sharing

The bar at the bottom of the room has the call controls.

ButtonWhat it does
🎤 Mute / UnmuteTurns your microphone off or on. A 🔇 icon appears on your tile for everyone else.
📷 Stop video / Start videoTurns your camera off or on. When off, others see a letter avatar instead.
🖥 Share screenYour browser asks what to share (screen, window or tab). Your video tile switches to it. Click Stop sharing or use the browser's own stop button to go back to your camera.
LeaveLeaves the room and returns to the start page.

Click any video tile to make it larger and click again to shrink it. This is handy when someone shares a screen.

Use headphones if you can. Without them the microphone can pick up your speakers and cause echo.

If the host has turned off "Participants can unmute themselves" or "turn on video", the mic, camera and screen buttons will tell you the host disabled them.

Chat and files

Chat

The Chat tab shows messages from everyone in the room, along with notices when people join or leave. Messages are not saved. Anyone who joins later does not see earlier messages, and everything is gone when you leave.

Sending files

  1. Open the Files tab and choose a file (up to 2 GB).
  2. Everyone in the room sees an offer with Accept and Decline buttons. Nothing is sent to someone until they accept.
  3. On Chrome or Edge on a computer, Accept asks where to save the file and writes it straight to disk, so even huge files work. In other browsers the file is collected in the browser and a Download link appears at the end.
  4. Progress bars show the transfer. Receivers can Cancel at any time.

Only people in the room when you offer the file can receive it, and it is not stored anywhere afterwards. Keep the tab open until it finishes. If the sender or receiver leaves, the transfer stops.

About very large files: a 2 GB transfer can take many minutes and depends on both internet connections. It is best sent to one or a few people, because you upload a separate copy to each person who accepts. On phones, and in Firefox or Safari, files over about 500 MB may run out of memory, so use Chrome or Edge on a computer for those.

The code editor

Open the Code tab. The first time, it loads the same editor engine that powers Visual Studio Code (called Monaco). That takes a few seconds and needs an internet connection. If it cannot load, MeetRoom falls back to a basic text box that still syncs between everyone.

Editing together

  • Everyone edits one shared document at the same time. Changes appear instantly, and if two people type in different places nothing is lost.
  • You see other people's cursors and selections in their own color. Hover a cursor to see whose it is.
  • People who join later receive the current code automatically.
  • Pick a language from the drop-down. It changes for everyone, so colors and checking match.
  • Click Expand to widen the side panel for more room (and Shrink to go back).

Editor features

  • Syntax colors, line numbers, code folding, bracket matching and colored bracket pairs
  • Auto-closing brackets and quotes, auto-indent, and word suggestions
  • Find and replace, multiple cursors, and move or copy lines (see the shortcuts below)
  • Commands button (or F1) opens the command palette with every editor action
  • Format button tidies the code (Shift+Alt+F)
  • Copy copies everything and Download saves it as shared.js, shared.py and so on, based on the language

Error checking

Problems are underlined in red (errors) or yellow (warnings) as you type. Hover the underline to read the message. The bar under the editor shows the cursor position and error counts, and Next problem (F8) jumps to the next one.

LanguageWhat gets checked
JavaScriptSyntax errors, plus suggestions as you type
TypeScriptSyntax and type errors, with quick fixes (Ctrl/⌘+.) and formatting
JSONInvalid JSON, plus formatting
CSSInvalid or unknown properties, plus formatting
HTMLTag suggestions and formatting
PythonUnclosed or mismatched brackets and quotes, missing : after if/for/def and similar, Python 2 style print, and mixed tabs and spaces
Java, C++, Go, Rust, SQLUnclosed or mismatched brackets, unclosed strings and unclosed comments
Markdown, plain textColors only
The checks for Python, Java, C++, Go, Rust and SQL are basic. They catch common typos but are not a real compiler, so code with no underlines can still have bugs. You can turn all checking off in Settings.

Undo tip: if two people edit the same spot, undo (Ctrl+Z) can behave in surprising ways because it works on your own typing. Copy anything important before experimenting.

People and host controls

The People tab lists everyone with their mic and camera status. The host also sees buttons next to each guest.

Host actionEffect
MuteTurns that person's microphone off. They can unmute again unless you disabled that.
Stop videoTurns their camera off and stops their screen share.
RemoveSends them out of the room. They can rejoin with the code.
BanRemoves them and blocks them from rejoining (see below).

In Settings → Host controls the host can:

  • Turn off "Participants can unmute themselves" so guests stay muted until the host allows it
  • Turn off "Participants can turn on video / share screen"
  • Click Mute all or Stop all video

Only the host's browser can send these commands. Other people cannot pretend to be the host.

Honest limit: these controls are enforced by each guest's browser. They work for normal use, but someone who deliberately modifies the page code could ignore them. Stronger enforcement needs a dedicated video server.

If the host closes the page, host controls are unavailable until they return. The host can get back into their room from the same browser by joining with the code again.

Bans

  • Click Ban next to a person in the People tab. They are removed and see "You have been banned from this room."
  • If they try to rejoin, they are removed again, and other guests disconnect from them too.
  • The Banned people list in Settings → Host controls lets you Unban anyone.
  • The ban list is kept in the host's browser, so it is still there if the host leaves and returns.
Bans are tied to a random ID stored in each person's browser. They stop casual rejoining, but someone who clears their site data, uses a private window or switches browser could get back in. If that happens, ban them again, or create a new room and share the new code only with trusted people.

Click ⚙ (top right of the room, or Settings on the start page). Everything is saved in your browser.

If calls stutter, lower Video quality first.

Themes

Themes live on the Home tab. There are three built in: Midnight (dark), Daylight (light) and Sunset (warm dark). You choose two things separately:

  • Interface theme for the home page, menus and settings. It can also be System, which follows your device.
  • Meeting theme for the video room, chat and code editor. It can be Same as interface or any of the three.

For example, you can browse the app in Daylight and sit in meetings in Midnight. Inside a meeting, the 🌓 button in the top bar cycles the meeting theme.

Troubleshooting

The browser never asks for my camera or microphone

Check that you have not blocked the permission for this site (click the lock icon in the address bar and allow camera and microphone, then reload). Also close any other app that may be using the camera, such as another video call.

"Could not reach the connection server"

MeetRoom uses a free public connection service to introduce people to each other. Check your internet, and check that a firewall, VPN or ad blocker is not blocking peerjs.com and cdn.jsdelivr.net.

We joined the same room but cannot see or hear each other

Some company, school or mobile networks block direct connections between devices. Try another network (for example mobile data instead of office Wi-Fi) and turn off any VPN. Also confirm everyone is on the exact same code.

Video is choppy or the page is slow with many people

Everyone sends video to everyone else, so load grows quickly. Lower Video quality in Settings, ask people to turn cameras off when not needed, and keep cameras-on groups to about 4 to 6 people.

I hear an echo

Use headphones, or mute when you are not speaking. Keep Echo cancellation on in Settings.

The code editor never loads

It downloads from cdn.jsdelivr.net, which must be reachable. If it cannot load within about 25 seconds you get the basic text box instead. Reload to try again.

"This room is full"

All 10 spots are taken. Ask someone to leave, or start a second room.

The host controls are missing

Only the person who clicked Start meeting is the host. If you created the room, make sure you rejoin from the same browser you created it in.

Screen sharing is not available

Most phones and some tablets cannot share their screen from a browser. Use a laptop or desktop for that.

Sending feedback

  1. On the home page, open the Feedback tab.
  2. Choose a type (Idea, Bug, Praise or Other), optionally give a star rating, and write your message.
  3. Add your name and email only if you would like a reply, then click Send feedback.

Your message is emailed to the person who runs this site. Please do not include passwords or private information. If automatic sending fails, the page offers a link to send it with your own email app instead.

Limits and privacy

TopicWhat to know
Room size10 people including the host.
PerformanceBest with 4 to 6 cameras on. Beyond that, expect lower quality. Very large meetings need a video server.
FilesUp to 2 GB each, sent live to people in the room who accept them, never stored.
HistoryNothing is recorded or saved: no chat history, no recordings, no stored code. Download the code before you leave.
Who can joinAnyone who has the code. There are no accounts or passwords.
EncryptionVideo, audio and data go directly between browsers over encrypted WebRTC connections.
What the connection service seesA public service helps people find each other. It sees the room-based ID and the network addresses needed to connect, not your video, chat, files or code.
Stored in your browserYour settings, your name, a random browser ID (used for bans), and for hosts, which rooms they created and their ban lists.
FeedbackWhatever you type in the Feedback tab is sent by email to the site owner through the FormSubmit service. It is not part of any meeting.
Loaded from the internetPeerJS, Yjs and the Monaco editor are loaded from the jsDelivr CDN.

Do not use MeetRoom for highly sensitive meetings without adding authentication and your own servers.

Tips for a good meeting

  • Use headphones and sit somewhere with good light facing a window.
  • Mute when you are not speaking, especially in bigger rooms.
  • Lower Video quality or turn off cameras if the call is choppy.
  • Send the invite link rather than the bare code. It fills the code in for people.
  • Download the shared code before you leave. Nothing is saved once the room is empty.
  • Hosts: ban or remove anyone who should not be there, and think twice before posting the room code publicly.
